## 核对及修正

| 环节 | 当前官方网页 | 本项目处理 |
| --- | --- | --- |
| 应用标识 | `cx-dev#cxstudy` | 原值正确，保留 |
| 登录凭证 | Cookie 认证请求 `GET https://learn.chaoxing.com/apis/user/getUserImToken`，附带 `crossOrigin=true`，检查 `result=1`，使用 `msg.uid` 和 `msg.hxToken` | 新增 `Chaoxing.im_session()`，连接时实时获取，不再使用保存的 IM 密码登录 |
| SDK 登录参数 | 官网模块版 MiniCore 接受 `username/accessToken` | 本项目完整 SDK 4.24.0 接受 `user/accessToken`，按本地 SDK 实现使用参数，未照搬模块版的 `username` |
| 设备类型 | 默认 Web 类型 `16`，没有强制改为 Linux | 移除 `osType=2` 覆盖。旧报告中的 Linux 兼容方案已被当前官方网页证据取代 |
| 设备标识 | 官网生成并缓存浏览器 UUID，结合用户标识；SDK 默认固定设备模式 | 使用完整 SDK 默认的浏览器本地固定标识，移除所有安装共享的硬编码名称；复用连接中的请求和已连接会话 |
| REST 主机 | `https://a3-vip6.easemob.com`，登录成功后重新赋值以防 DNS 覆盖 | 登录前后均指定该主机 |
| 群聊 | 官网主界面读取 `getServerConversations`；SDK 另支持查询所有已加入群聊 | 本项目保留“已加入群聊”语义，使用 `getJoinedGroups`，页码从 0 开始。带 `needAffiliations` 时，本地 SDK 返回 `entities`，字段为 `groupId/groupName`；原列表解析和界面字段均修正 |
| 历史消息 | `getHistoryMessages` 使用群聊类型、起始游标 `-1`、向前搜索和 `cursor/isLast` | 显式设置起始游标和搜索方向；不再因解码后的消息不足一页提前停止，检查 `isLast` |
| 接收消息 | 官网注册文本、命令及多种媒体回调 | 本项目面向课堂活动，保留文本、自定义、命令消息，不宣称完整聊天媒体支持 |
| 设备数量限制 | 服务端仍可拒绝新连接 | 保留 214 中文提示和主动断开功能；修正接入参数不能保证绕过或解除服务器设备上限 |

## 系统通知噪声及已读状态修复

排查时，本地缓存存在 `CMD_READ_ACK`、`CMD_GROUP_MSG_READ` 和 `REVOKE_FLAG` 命令消息（数量省略）。旧实现把所有命令消息当作普通消息，并将没有正文的命令统一回退为“系统通知”，从而产生大量无意义气泡。

现按当前官网的可见命令白名单显示 `CMD_MESSAGE_TIP` 和 `CMD_GROUP_CHAT_INVITATION`，分别解析提示正文和入群名单，以居中通知样式展示。其他内部命令不进入聊天正文、消息预览或本地新增未读计数；旧缓存也应用同样过滤。多端已读、SDK 单条/会话已读和撤回信号单独更新状态。保留原始缓存，不删除用户历史记录。

会话列表和头部显示未读数量、本地已读、无未读或未同步。本人发出的私聊消息在收到确切回执或 SDK `isRead=true` 时显示“已读”；明确为 `false` 时显示“未读”，缺少回执和字段时显示“待确认已读”。群聊只在收到有效已读人数时显示人数，不把本地查看当作所有群成员已读。已读回执按账号、会话、消息持久保存；不根据对方的新消息推断此前所有消息均已读。

真实浏览器确认：群聊正文中不再出现无内容系统命令气泡，正常正文、图片、活动卡片仍保留；私聊和群聊头部显示本地状态，本人发出的既有私聊消息显示“待确认已读”。历史接口此次未返回私聊的 `isRead` 字段。仅通过模拟事件验证收到回执后的“已读”和群人数标签，未生成真实发送或回执测试流量，也未测试消息发送。当前实现监听并展示收到的回执，不新增自动向对方发送阅读回执或远端清零未读的动作。

17 项 Python 测试、9 项 JavaScript 测试及 Ruff 检查通过。新增覆盖内部命令过滤、合法群通知、回执状态缺失、跨账号同步拒绝和精确消息回执路由。
