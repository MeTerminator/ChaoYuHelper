## 实际读取链路

1. 通过 `GET https://mooc1-api.chaoxing.com/mycourse/backclazzdata` 更新当前账号课程缓存。
2. 每科读取 `https://mooc1.chaoxing.com/visit/stucoursemiddle`，获取平台提供的 `workEnc`、`enc`、`t` 与作业入口。
3. 请求入口中的 `/mooc2/work/list` 或 `/mooc-ans/mooc2/work/list`，按页面提供的分页链接读取全部列表。
4. 按课程 ID、班级 ID、作业 ID 去重，附带课程信息。顺序读取课程、课程间隔 1 秒；单科失败保留其他科目的结果，并明确提示汇总不完整。

只读取列表，不请求未交作业的 `task` / 作答表单，不自动提交。作答仍须进入现有页面后由用户点击“开始作答”。

## 界面与接口

- 左侧“我的作业”，初始地址 `/?section=homework`。
- 当前账号所有可读取课程的作业汇总，未提交及其他状态优先，支持搜索、科目、状态筛选和每页十项。
- 展示平台原始状态与列表附带信息，不推测缺失的截止时间。可进入课程作业、作答或记录；作业页提供返回汇总入口。
- 切换账号重新读取，旧请求结果通过页面代次隔离，避免跨账号显示。
- `GET /api/accounts/{account_id}/homework`，沿用 Bearer Token 认证，返回 `works`、`courses`、`errors`；`works` 每项附 `course`，`errors` 每项含 `course` 与 `error`。同账号的所有网页和 API 共用 120 秒刷新间隔及加密缓存，验证码触发后暂停 300 秒；失败课程保留上次作业并明确标记缓存状态。

## 连续刷新触发验证的修复

真实只读诊断确认：课程入口返回 HTTP 302，跳转到 `/antispiderShowVerify.ac`，最终返回 HTTP 202，标题为“提示页面”，内容为“【9010】操作异常，请输入图片中的验证码”。原解析器将缺少 `workEnc` 的验证页误报为课程没有作业入口。

已针对该验证码响应抛出专门异常，停止后续课程请求，不自动重试。课程改为串行读取，间隔 1 秒；账号锁合并多网页 / API 同时刷新；120 秒内复用缓存，触发验证码后 300 秒内只读缓存。缓存和刷新截止时间按账号加密持久保存，页面重载和服务重启不绕过间隔。单科失败保留上次作业，界面标明旧数据可能不准确。删除账号同时清理缓存。

模拟验证覆盖验证码识别、八个并发刷新共用一轮读取、跨服务重启限速、账号隔离、首次验证失败即停止其他课程、旧结果保留，以及冷却期连续刷新不产生平台请求。后续已接入前端手动输入验证码流程，见下节。

## 在项目内输入验证码

继续检查 APK 可提取 `com/chaoxing/fanya/aphone/ui/VerifyCodeActivity` 与 `com/chaoxing/mobile/study/course/VerifyWebActivity` 类名，但加固使相关方法体无法直接还原，不能仅凭类名断言完整调用链。本次实现依据实际受限课程请求返回的官方验证 HTML，而不是猜测客户端协议。

实际页面包含未声明 method 的表单（默认 GET），action 为 `/html/processVerify.ac`，隐藏字段 `app=0`，用户字段 `ucode`，限制四位字母或数字。页面脚本将验证码图片设为 `/processVerifyPng.ac?t=<随机数>`。这属于访问风控图片验证码，与已有滑块验证码协议不同。

新增 `ChaoxingAccessVerification`：用当前账号原 HTTP 客户端读取验证页面和验证码图片，沿用 Cookie；仅接受固定官方提交地址和已知字段。验证码图片校验格式、大小后以内存 data URI 返回前端，不通过独立浏览器会话完成验证。前端自动展示图片、输入框、“换一张”和“验证并继续”。换图使旧图片令牌失效；同一账号并发操作共用账号锁，验证码和图片只保存在服务端内存，不向前端暴露 Cookie。

提交使用官方表单的 GET 方法和同一账号会话。不将 HTTP 200 当作验证成功：提交后重新读取只读课程入口，仍有风控则提示错误 / 过期，成功恢复课程作业入口后才解除汇总冷却并自动读取作业。未打开作答题目或提交作业。

验证结果：真实已保存账号已成功获取官方 PNG 验证码图片，未替用户识别或提交真实验证码。模拟 HTTP 验证了同会话提交、错误码不通过、换图使旧令牌失效、外域提交地址拒绝、验证后只读探测和恢复读取。模拟浏览器验证了图片展示、错误提示、换图、用户输入提交、通过后恢复列表，未出现浏览器错误。截图 `artifacts/homework-captcha.png` 使用模拟验证码；真实验证码是否通过仍由平台判定。

## 默认仅读取数据库缓存

按用户要求，将页面默认读取和主动刷新分开。现在 `load_summary` 的默认模式永久优先读取数据库快照，不因 120 秒间隔到期而自动访问平台；首次没有快照也不请求平台，显示首次加载提示。刷新按钮和验证码验证通过后的继续加载显式使用 `refresh=True`；REST 增加 `refresh` 查询参数，默认同样只读缓存。已有账号隔离、加密持久化、失败保留与请求冷却机制继续保留。

默认展示缓存中的验证码提示时也不自动获取验证码图片，避免仅进入页面就触发额外平台请求。模拟验证覆盖无缓存默认读取零请求、过期缓存默认读取零请求、重建服务后仍读取数据库、主动刷新及验证码验证后恢复读取。
