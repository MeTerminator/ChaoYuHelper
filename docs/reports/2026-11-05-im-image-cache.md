# 消息图片预缓存验证

日期：2026-11-05。

## 行为

后端连接消息服务后，会在后台预取已有本地消息、会话摘要及可访问的云端历史页中的图片和头像；新收到的图片也会自动预取。所有网页通过需要管理员登录的同源签名接口 `/media/im/image` 读取同一个账号的磁盘缓存。

后台历史读取最多两路，图片预取最多两路；总图片下载最多四路，当前网页请求可以使用剩余下载空间。同账号同地址的并发请求合并为一次下载。图片在网页中提前加载、异步解码，并预留显示比例，失败时提供“重新加载”；头像失败时显示文字占位。

缓存位于 `data/cache/im/`，上限 256 MB / 4096 张，保留 7 天，单张最多 8 MB。缓存文件采用不含原地址的哈希名并限制为本地用户可读；缓存密钥按账号生成，设备和消息鉴权信息仍保存在加密 Store。作业图片继续保留原有缓存目录、1 小时有效期、64 MB / 512 张上限。

## 验证

使用临时加密数据库、模拟账号、HTTP MockTransport 和模拟消息连接，运行真实 NiceGUI 服务与两个真实 Chromium 网页。没有使用真实消息账号或下载真实联系人图片。

| 检查 | 证据 |
| --- | --- |
| 启动后无需网页即可预取 | 多页云端历史中的两张图片和一张头像在网页打开前已缓存，每个地址仅下载一次 |
| 页面读取共享缓存 | 两个网页均显示图片；图片 `src` 使用 `/media/im/image`、`loading=eager`、`decoding=async`；平台下载次数未增加，网页未直接访问平台图片域名 |
| 图片接口访问控制 | 未登录访问返回 303；签名篡改返回 403；有效签名返回真实 PNG 和 `private, max-age=86400` |
| 多网页并发去重 | 30 个同账号同图片并发请求只产生一次源站下载 |
| 账号隔离 | 相同源地址在两个账号下使用不同的缓存记录 |
| 缓存持久化 | 重建缓存对象后直接读取原磁盘图片，未重新下载 |
| 受限环信图片 | 模拟请求在后端带 Token 与文件密钥，跨域跳转到 CDN 时移除这两个鉴权头 |
| 图片地址与内容校验 | 不支持的地址、跳转到回环地址和非图片响应均被拒绝 |
| 有界存储 | 缩小测试容量后，文件数量和字节量均按上限清理旧图片 |
| 无网页时收到新图片 | 关闭消息页面后注入新的模拟图片消息，仍自动下载到缓存 |
| 作业图片回归 | 路由、有效期、容量上限及图片下载均保持可用 |
| 消息生命周期回归 | 自动连接、双页面同步、显式模拟发送、断线重连、凭据续期、Chromium 异常恢复、删除账号及关闭服务均通过 |

页面截图已检查，图片、头像和消息布局正常；前端无 JavaScript 异常，服务退出无异常堆栈。`ruff check app main.py` 与 `git diff --check` 均通过。

首次后台扫描尚未完成时，未缓存图片仍需要下载；平台过期、无权限、超出单张上限的图片无法缓存。超出总缓存容量时会淘汰旧图片，本实现不承诺无限量保存全部历史图片。

接口依据：[环信文件下载](https://docs-im.easemob.com/start/100serverintegration/40fileoperation)、[Quasar QImg](https://quasar.dev/vue-components/img/)，并与仓库锁定的 SDK 下载实现核对。

## 502 修复补充

用户反馈真实环信图片返回 502 后，使用已有账号和同一图片进行了只读复现。根因为 `provider.request()` 会在平台 HTTP 客户端注册 `guard_request`，该检查仅接受平台域名；消息图片复用此客户端时，环信请求被本地检查拒绝。原模拟客户端未注册此钩子，因而先前联调漏检。

消息图片现使用独立的账号 HTTP 客户端，复制有域限制的 Cookie，继续使用图片下载器逐跳校验地址；原平台客户端的检查保留。独立客户端在账号删除、重新登录和服务退出时关闭。

真实只读复验：用户提供的图片地址经环信 302 跳转后返回 HTTP 200，内容通过 JPEG 校验，并成功写入缓存。未在报告中记录账号、图片地址、文件密钥、Token 或图片内容。

新增回归使用真实 `Chaoxing` 实例，先通过平台请求安装真实地址检查钩子，再用模拟网络验证：原平台客户端仍拒绝环信地址，签名图片接口通过独立客户端跟随 302 返回 JPEG 200，后续读取命中缓存，账号删除后客户端关闭。图片缓存并发、账号隔离、作业图片、双网页显示及消息连接生命周期回归均通过；静态检查通过。
