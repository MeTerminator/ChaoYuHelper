# 后端共享消息连接验证

日期：2026-11-05。

目标：后端启动 → 按学习通账号维护连接 → 网页打开“群聊与消息”自动同步 → 实时事件分发给所有网页；断线恢复、网页关闭与账号删除有独立生命周期。

## 实现

- `app/im_service.py` 在服务启动时为已保存的学习通账号创建维护任务，每个账号一个隔离的 Chromium 上下文及环信连接，共享一个无头浏览器进程。
- 网页通过 NiceGUI 后端调用读取会话、漫游历史和发送文字，不再加载环信 SDK 或接收消息 Token。
- 后端接收实时消息和控制事件，先写入加密 Store，再通过有界事件缓存供网页同步。没有网页打开时仍接收并缓存。
- 断线重新取得凭据，按 2–60 秒退避重试；凭据即将到期时调用 SDK 续期。浏览器进程退出后重新创建。设备存储按账号加密持久化。
- SDK 4.24.0 将构造参数 `autoReconnectNumMax: 0` 当作默认值 5，需要在构造后显式赋值为 0，使重连仅由后端维护。保留 Web 设备类型 16。
- 删除账号、重新登录和后端退出时清理连接；网页关闭不清理共享连接。发送失败不会自动重发。

首次部署需要执行 `uv run --locked playwright install chromium`。部署仍使用单个 NiceGUI 服务进程；多个独立后端进程各自维护连接，不共享跨进程连接。

## 验证证据

静态检查：`ruff check app main.py`、Node 语法检查与 `git diff --check` 通过；IM 构建产物已重新生成。

使用临时加密数据库、模拟账号和消息 SDK 启动真实 NiceGUI 服务，以 Playwright 同时操作两个已登录页面，验证以下完整路径：

| 边界 | 结果 |
| --- | --- |
| 无网页访问时启动服务 | 自动创建并连接账号，凭据读取一次 |
| 两个页面点击“群聊与消息” | 自动显示群聊及历史，后端仍只有一个账号连接 |
| 浏览器运行状态 | 网页不存在 `window.courseIM`，不接收 IM Token，无 JavaScript 异常 |
| 模拟实时消息 | 两个页面同时显示，后端加密存储已更新 |
| 页面手动发送模拟文字 | 通过共享后端连接发送，两个页面同步显示 |
| 模拟断线 | 自动重新获取凭据并恢复，设备标识保持一致 |
| 模拟凭据即将过期 | 续期后连接保持在线 |
| 关闭后端 Chromium 进程 | 自动重建浏览器和连接，恢复原设备标识 |
| 关闭全部网页 | 后端仍连接 |
| 删除账号并运行连接协调 | 维护任务清理，连接不再创建 |
| 退出服务 | 正常结束，无服务端异常堆栈 |

另在 Chromium 中加载真实已锁定的环信 SDK，替换网络登录和发送入口以避免真实操作：确认构造成功、并发连接请求合并、重试上限为 0、设备类型为 16、登录参数和续期调用正确。

以上为隔离模拟联调；没有连接真实学习通消息账号或向真实联系人发送测试消息。真实平台可用性仍取决于账号登录态、平台设备上限与网络。

参考：[Playwright Python Library](https://playwright.dev/python/docs/library)、[环信连接文档](https://doc.easemob.com/document/web/connection.html)，以及仓库锁定的 SDK 类型定义与实现。
