## 修复内容

1. 雨课堂请求补齐按 Cookie 域、路径匹配的 `x-csrftoken`、`sessionid`、`x-uid` 会话头。
2. 登录前通过只读账号信息请求初始化 CSRF Cookie。
3. 接入官方网页版 RSA 密码登录流程：读取公钥，提交加密密码与用户手动完成的验证码结果。参考来源是雨课堂当前官方 `/web` 页面及其自带 JavaScript。
4. 默认使用网页登录；原 App 登录作为可选方式保留。学习通也默认使用本次已验证可用的网页登录方式。
5. 区分雨课堂 App 与 Web 会话的 `x-client` 请求头，持久化登录方式；修复网页登录后当前课堂查询返回 `UNAUTHENTICATED` 的问题。
6. HTTP 错误显示状态码和接口路径，避免只提示笼统网络故障；不输出请求参数、密码或会话值。
7. 新增严格只读测试模式：登录及读取端点逐项列入白名单，提交类端点在 HTTP 请求发出前被阻止。

## 测试限制

实际没有调用签到、扫码入课堂、课堂 checkin、答题、补交、投票提交、问卷提交、讨论回复、评分、人脸提交或图片上传等业务修改接口。真实业务操作记录为 0。

本轮对修改类功能只做代码审查；回归测试中的提交、登录和加密测试均使用本地临时数据与模拟 HTTP 响应，不请求真实平台。30 项回归测试通过，Ruff 检查通过。

为了读取 PPT 而调用 checkin 可能产生签到或入课堂效果，因此没有执行，真实 PPT / 课堂授权和提交功能仍不在本次实测结论内。学习通未抽到的活动类型也不声称已经完成真实接口验证。

联调会话与加密密钥不纳入版本控制，不在报告中记录具体账号的本地会话状态。

## 当前服务

后端保持只读测试模式运行：

```bash
COURSE_HELPER_READ_ONLY=1 uv run python main.py --no-open --port 8080
```

浏览器地址：<http://127.0.0.1:8080>。网页有只读模式提示。

`app/read_only.py` 维护允许登录和读取的精确 HTTP 方法 / 域名 / 路径；包括四个官方雨课堂服务器。`scripts/read_only_check.py` 可复用只读联调方法，凭据只从标准输入进入内存。脱敏计数和响应结构保存在 `artifacts/read-only-*.json`，不含实际账号数据。
