# 开发与维护

## 项目结构

```text
main.py                    课程助手路由、启动参数与服务入口
app/
  api.py                   Bearer Token 认证的 REST API
  auth.py                  管理员初始化、登录、凭据修改及 HTTP / WebSocket 访问控制
  ui/                      浏览器界面：路由、Dashboard 组合入口及业务视图
  service.py               账号会话、课程缓存、设置与批量操作
  auto_sign.py             学习通课程实时消息触发的自动签到、随机延迟、持久化去重与任务清理
  sign_code.py             有界日期时间模板校验和签到码生成
  im_service.py            后端共享环信连接、断线重连、历史图片预取与多网页分发
  im_media.py              消息图片与头像的同源缓存、鉴权及后台下载
  store.py                 SQLite + Fernet 加密存储
  activity.py              活动解析、参考答案、选人去重与课堂计时
  homework/                作业页面、签名表单、题目控件、附件与提交报文解析
  crypto.py                协议加密、签名和图片 CRC
  media.py                 PPT 图片格式识别
  providers/
    base.py                HTTP 会话、请求地址校验及公共错误
    chaoxing/              学习通客户端及按业务划分的协议能力
    rain.py                雨课堂 HTTP / WebSocket 协议
  static/                  样式、环信 SDK 源码与打包产物
docs/                     使用、开发、API 与历史验证报告
data/                     本地账号数据、密钥和 Token（不纳入版本控制）
.nicegui/                 浏览器偏好等状态（不纳入版本控制）
```

项目已从旧子目录迁移至根目录。所有启动命令在根目录执行，源码通过文件位置解析静态资源和默认数据目录。

模块边界、依赖方向与新增功能的落点见 [架构与模块职责](ARCHITECTURE.md)。`app.ui`、`app.providers.chaoxing` 和 `app.homework` 保留原有导入入口，实际实现位于对应包内。

## 环信资源构建

运行时使用已提交的 `app/static/im.js`，不需要 Node。后端通过 Playwright 无头 Chromium 运行环信 SDK，首次部署执行 `uv run --locked playwright install chromium`（Linux 可使用 `install --with-deps chromium`）。一个服务进程共用浏览器，每个学习通账号使用独立上下文和连接，设备存储按账号加密保存于 Store。浏览器页面通过 NiceGUI 后端调用复用连接，不接收 IM Token，不创建环信连接。断线或 Chromium 异常后由后端重新获取凭据并按 2–60 秒退避持续重连；Token 即将过期时续期。服务关闭、删除账号或重新登录时会清理旧连接。修改 `app/static/im-source.js` 后再执行：

```bash
npm ci
npm run build:im
```

保留 `package.json`、`package-lock.json` 和构建产物中的许可说明；`node_modules/` 可清理。锁定的第三方版本和许可说明见根目录文档。

### 消息图片缓存

连接成功后在后台扫描本地消息、会话、群聊及其可访问的云端历史页，预取消息图片与头像，不发送已读回执、不自动发送消息。后台历史读取最多两路，图片预取最多两路，总下载最多四路，给当前网页请求保留下载空间。预取失败不会中断消息连接；新收到的图片、页面加载的历史和资料也会进入预取流程。

图片通过需要管理员登录的 `/media/im/image` 签名接口返回，按账号与原地址合并并发下载，原始地址逐跳校验。消息图片使用独立、按账号隔离的 HTTP 客户端，复制平台 Cookie 的域限制，不复用只允许平台地址的请求检查钩子；账号删除、重新登录及服务关闭时一并清理。受限环信图片使用后端持有的 Token 和加密保存的文件密钥，重定向到其他 CDN 时不携带这两个头。接口返回私有浏览器缓存头，同一天生成的签名链接保持稳定；图片缓存会跨进程重启复用。缓存目录为 `data/cache/im/`，上限 256 MB / 4096 张、有效期 7 天、单张上限 8 MB。图片预取按可读取的历史范围进行，平台已过期或无权限的图片无法预取；容量不足时按缓存访问顺序淘汰。

作业图片继续使用独立的原缓存目录、1 小时有效期与 64 MB / 512 张上限；共用下载去重和图片校验实现。消息图片与头像在网页中使用提前加载和异步解码，消息图片根据尺寸预留显示比例；失败时可点击“重新加载”。

## 真实账号联调

应用以正常模式运行，界面中手动点击会执行对应的平台操作。开发回归使用模拟 HTTP、SDK 和临时数据库；个人账号联调仍应按测试范围选择读取接口。

凭据不得写入源码、命令行参数、共享日志或报告。本地账号数据、密钥和 Token 由 `data/` 管理，该目录不纳入版本控制。

## 故障排查

| 情况 | 检查方式 |
| --- | --- |
| 服务未启动 | 执行 `uv run --locked python main.py --no-open` 查看错误；用 `curl http://127.0.0.1:8080/health` 检查健康状态 |
| 端口被占用 | 用 `--port 8088` 等其他端口启动，并打开对应地址 |
| 迁移后提示找不到 Python 或脚本 | 在根目录执行 `uv sync --locked`；不要继续使用旧子目录的解释器路径 |
| 课程空白或账号消失 | 核对平台、雨课堂服务器和账号，手动刷新课程；平台接口可能要求重新登录 |
| 新设备验证 / 验证码错误 | 在界面中由用户完成验证，或选择对应的短信 / 二维码登录；不要连续重试或绕过验证 |
| `UNAUTHENTICATED` | 核查服务器、会话是否过期，以及保存的 Web / App 登录方式是否与 `x-client` 匹配 |
| 消息服务登录设备数超限（214） | 先退出其他电脑、浏览器或旧版助手的消息会话，再连接；仅关闭页面可能需要等待服务端释放名额。本应用所有网页复用后端按账号维护的连接；关闭网页不会退出消息服务，停止后端服务会释放连接。固定设备标识无法提高平台上限 |
| 解密失败 | 确认数据库与 `.key` 来自同一次备份；不要替换或重新生成现有密钥 |

## 后续扩展

新增跨入口的业务编排放在独立服务模块，`app/service.py` 负责账号、缓存、设置与服务生命周期；平台协议请求集中在 `app/providers/`。界面和 REST API 通过服务层获取平台能力；纯解析与校验放在领域模块。`auto_sign.py` 已支持学习通课程实时消息触发的位置及签到码自动提交，与手动操作共用账号锁，按账号和活动持久化去重，并记录结果；历史缓存入口不触发任务。后续定时任务、AI 和其他无人值守流程增加时须单独设计启用条件、账号隔离和操作记录。

## 作业适配约束

列表读取先访问官方课程入口，提取 `workEnc` / `enc` / `t`，按官方 `course-stu.js` 的字段请求作业列表。已提交记录直接请求 `view`，不能为了查看记录先请求 `task`，后者可能跳到作答页并启动计时。

`homework_open` 必须由用户点击“开始作答”触发。提交仅使用当前账号刚加载的表单签名和隐藏字段，不接受界面自造的签名。题目数量和类型不完整时禁止提交；成功后移除内存表单，防止再次点击同一份提交。草稿使用与账号、作业 ID 关联的加密记录，不会自动保存到平台。

作业列表、详情结构来自官方真实只读页面；作答表单和提交协议参考现有表单约定及[公开实现源码](https://greasyfork.org/fr-CA/scripts/583231/code)，采用独立实现。手动作答仅用模拟 HTML / HTTP 验证，没有打开用户的未交作业。已补充签名分页合并、图片 / 文件附件、排序 / 连线内部值映射和多编辑器字段的模拟验证；不要把模拟覆盖描述为真实作业提交成功。排序与连线字段另参考[题目控件解析源码](https://github.com/iPycc/Fk-Chaoxing-Extension/blob/main/modules/question/parse/dropdown.js)，采用独立 Python 实现。

IM 适配保留 `easemob-websdk@4.24.0` 的默认 Web 设备类型 `16`，从 `GET https://learn.chaoxing.com/apis/user/getUserImToken?crossOrigin=true` 的 `msg.uid` / `msg.hxToken` 获取登录凭证，再调用 `open({user, accessToken})`。登录前后均指定 `https://a3-vip6.easemob.com` 为 REST 地址，避免 DNS 发现覆盖。固定设备标识由 SDK 在后端隔离的浏览器上下文中生成，其存储状态按账号加密保存，重启与重连时恢复。群聊带 `needAffiliations` 时从 `entities` 读取 `groupId/groupName`；历史消息按 `cursor/isLast` 向前分页。详见 [官方消息页核对记录](reports/2026-11-04-im-review.md)。

历史 IM 回归覆盖会话分页、群聊 / 私聊路由、历史游标、账号隔离、资料缓存和展示归一化；测试目录现已移除。实际只读验证见上述核对记录。后端创建连接上下文时从本地读取已构建的 IM 脚本，不依赖网页的静态资源缓存。

用户和群聊资料由 `im.chaoxing.com/webim/user/getUserInfoByTuid` 与 `/webim/huanxin/getGroupInfo` 读取，必须覆盖手机客户端默认请求头，使用网页的 `Accept: application/json, text/plain, */*` 等头；真实验证发现沿用手机头会得到 `text/plain;charset=ISO-8859-1`，中文名称已经在服务端退化为问号，无法仅靠客户端改编码恢复。

会话以 `chatType:targetId` 为键，私聊按消息方向选择对方 ID；消息、会话、草稿和本地已读时间均按账号存于加密 Store。漫游每页 30 条，通过 `cursor/isLast` 加载更早消息。发送仅由按钮或 Ctrl+Enter 调用 `sendText`，当前支持纯文字，限制为 5000 UTF-8 字节；失败或超时保留草稿，不自动重发。测试不得向真实联系人发送消息。


### 作业分页与附件

上游分页只跟随页面实际提供的官方链接，不拼造签名或提交地址。合并后校验题目 ID 和总数；本地界面将作业列表按每页 10 项、题目和记录按每页 5 项显示，翻页不销毁答案控件。排序按内部选项值序列提交，连线保留左侧内部编号，不能把界面显示的字母直接当成内部 ID。

附件调用既有云盘上传流程，单文件上限 50 MB，图片需要通过格式校验。上传记录以账号、作业和题目关联并加密保存；客户端只能选择该记录中的 Object ID。提交时编码图片或平台附件 HTML，不执行官方页面脚本。草稿的 `_attachments` 记录选中的附件，`_keep_existing` 记录是否保留平台原有的图片或附件；默认保留，防止只改文字时意外删掉已有内容。

HTTP 请求与重定向均校验目标是否为支持的平台地址。


### 学习通访问风控验证码

课程入口返回 `antispiderShowVerify.ac` / 9010 图片验证码时，停止批量读取，由“我的作业”界面展示验证码与输入框。`app/providers/chaoxing/access_verification.py` 负责官方表单、同会话图片和人工输入提交；`app/ui/access_verification.py` 负责展示及提交反馈；`homework_summary.py` 串行协调和解除冷却。访问风控验证码与 `captcha.py` 中的滑块验证码是不同协议。

提交后的只读课程探测必须成功后才能解除冷却，不得仅凭 200 / 重定向认定通过。验证码令牌与账号提供方绑定、三分钟过期，换图使旧令牌失效；不持久保存图片或用户输入，不把账号 Cookie 传给前端。


### 作业汇总数据库缓存

`load_summary(..., refresh=False)` 默认只读当前账号的 `homework-summary` 数据库记录，不按时间自动失效，也不请求课程或作业列表。没有缓存时返回空结果和 `cache_missing=true`，由用户点击“刷新全部作业”首次加载，不将这个空占位结果写入数据库。网页刷新、重新进入、账号切换、服务重启都沿用该规则；界面主动刷新及验证码验证成功后的继续加载显式传入 `refresh=True`。REST 通过 `?refresh=true` 显式更新。

刷新后的完整 / 部分结果继续通过 Store 加密持久保存，失败科目保留旧作业并标记。120 秒间隔只约束主动的平台请求，不能使页面默认读取转为网络刷新。缓存中的验证码提示在默认进入页面时也不自动请求图片，用户可主动换图验证；验证成功后重新读取作业并更新数据库。
